# Private release persistence

`PrivateReleaseStore` reuses the exact pinned Evidence persistence SDK and migration in a separate dedicated packaging database. It never opens the Evidence, intake or correspondence operational database. Authenticated scope-bound owner/researcher policy protects load and mutation. Context comes from a trusted gateway, not an HTTP body or model. Owner configuration changes require an explicit deployment migration; this adapter does not expose an owner/publisher-policy editor.

Create, propose, owner approval and correction commands use actor-bound idempotency plus optimistic storage revisions. Immutable manifest history, storage revisions, audit and outbox writes commit together. Idempotent replies are historical snapshots, not current release authorization. Every private metadata export checks the latest state, expiry, current exact artifact/decision bindings and strict boolean rights, consent and editorial decisions. It then compares/writes the same local revision and audits the prepared package before returning it. A failed or lost transaction acknowledgement returns no prepared package; a later attempt must load and check the current revision again.

The current-input resolver is a required trusted deployment component. It receives a captured authenticated context and exact proposed bindings, must look up authoritative current editions and decisions, and must honor the abort signal. Calls have a bounded deadline; unavailable services, malformed decisions or denial roll back. Resolver errors are sanitized. Form fields, document contents, unverified reports and model assertions cannot substitute for this component.

Local release changes are serialized by compare-and-write. An external rights/consent service can change after its read; the local database cannot atomically freeze another service. This adapter therefore issues only private metadata/source-companion exports under ordinary protected data access. It provides no external policy enablement, external manifest proposal, publisher handoff, delivery or withdrawal API. It is not an externally valid permission token. A future publishing gateway needs authoritative consume-time permission fencing and separately authorized destinations. No transport is included or activated.

Tests use the actual SDK migration under a restricted NOINHERIT, non-superuser, non-BYPASSRLS PGlite login. Seven integration tests plus six existing domain tests cover immutable approvals, exact source companions, current decision denial, changed editions, corrections, replay/stale commands, caller mutation, lost acknowledgements, scope/ownership and private-only policy. They also cover strict boolean decisions and bounded, redacted resolver failures. Embedded PGlite is not proof of independent network-session contention, real upstream service integration or live operational acceptance. Binary export rendering, accessibility review, private artifact storage and real publishing remain separate work.

Resolver deadline enforcement now checks monotonic elapsed time before admission and after result cloning as well as using a timeout timer. Blocking the event loop cannot make a late approval or private-export result timely. Abort signals close on every exit. Callback and cloning errors stay sanitized; late results cannot resume the transaction. This cannot preempt blocked JavaScript, undo callback side effects, or atomically freeze upstream decision services. Production resolver isolation/current policy and gateway qualification remain required.

Development checkpoint: all17 ordinary local tests/typecheck/build/registry pass. Four new restricted-migration groups reproduce late approval/export acceptance on prior source, reject asynchronous late results, sanitize callback/clone failures and close signals on success/failure. Installed exports and final-head CI remain pending. External publication remains disabled.
