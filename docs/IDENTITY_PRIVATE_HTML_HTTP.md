# Current Identity private HTML host adapter (partial PRC-005/006)

`./identity-private-html-http` exports `createIdentityPrivateHtmlHandler(store,membership,provider,policy,clock)`, a Fetch Request/Response handler. It opens no listening server and provisions no login, cookie, key, certificate or deployment. The host supplies the independently authenticated HUMAN session provider accepted by Identity's pinned `membership-session` SDK. That provider returns only actorId/requestId/session CSRF, never roles, scope or purpose. Each request reloads actual stored Identity human-owner authority. Packaging independently requires the fixed host owner list, scope/purpose and its existing private store policy. Identity and Packaging retain separate owning operational databases using the unchanged stable Evidence persistence SDK.

Only GET `/packaging/session` and POST `/packaging/private-html` exist. POST accepts exactly `{expectedRevision,manifestId}`; the finite positive revision must be the reviewed containing Packaging SQL edition. No proposal, approval, bootstrap, enablement, dispatch or publication route is added. GET returns only actor ID/scope/session CSRF. POST returns the accepted self-contained metadata HTML bytes as a fixed-name attachment, with private/no-store, nosniff, restrictive sandbox CSP, no-referrer and same-origin resource policy. Headers bind actual-byte SHA256, containing preparation revision and package hash. No source artifact content is retrieved. There is no server-side content storage or download/delivery receipt; a prepared SQL audit does not prove the client received the bytes. Already downloaded historical copies cannot be revoked.

Fixed exact HTTPS origin, Origin/Fetch Metadata checks and constant-time session CSRF are mandatory. POST uncompressed strict UTF8 JSON is bounded to16KiB/4096chunks and a monotonic deadline, captured BEFORE fresh Identity authentication. Accepted Identity bounds provider/metadata/copy/role resolution acceptance and closes every owned signal. Begun Identity SQL is awaited; host driver/connection/concurrency limits are still required. Host sessions, identity proofing, random session CSRF, current purpose/policy/owner configuration, trusted clock and TLS/ingress/header controls remain trusted. Diagnostic strings, snapshots and hashes are not authentication.

`PrivateReleaseStore.exportPrivateHtmlCurrent(context,expectedRevision,manifestId,clock,{signal?,timeoutMs?})` is the new owning action used by this handler. Legacy methods remain unchanged. The synchronous trusted clock is sampled AFTER the actual Packaging project lock/stored read, after current input resolution and after bounded rendering. Regressed/invalid/throwing clocks deny; monotonic stage deadlines and cancellation deny before the revision write. Exact private approval checks run again after rendering using the same captured current-input result. This prevents a stale request timestamp from accepting an approval which expired while waiting for the owning read/resolver/rendering. Audit request metadata is not invented SQL commit or delivery time. Clock observation is not a distributed permission/expiry fence: Identity or upstream decisions may change after their observations, and SQL/COMMIT or response delivery may outlive them. No token consumption, exactly-once external action or atomic cross-service revocation claim.

Begun SQL is awaited. A known completed preparation remains committed if cancellation arrives afterwards; bytes are withheld on observed post-commit cancellation with503 `preparation_unknown`. Driver/COMMIT acknowledgement loss is likewise UNKNOWN, never rollback, absence or retry permission. There is no command cache or automatic replay. Load authoritative owning state/history before a later explicit operation; an old expected edition conflicts after a committed preparation. Other unknown errors are sanitized; no private diagnostics are returned. This is a preparation API, not the Visual pending recovery protocol.
